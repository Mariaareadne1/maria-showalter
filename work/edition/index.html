Edition

Turn photographs into two-color halftone prints.

Edition turns a photograph into a print made of two inks. Each ink is a real halftone plate at its own screen angle; you can pick a plate up and push it out of register, then export the composite and both films at print resolution. Images never leave the browser.

01 — Overview

A printmaking table, not a filter.

Most “halftone effects” are a single screen laid over a photo. Edition models the parts of printing that make a two-colour print look like one: a separation into two plates, round dots at each plate’s angle, transparent inks overprinting, paper tooth, and plates that sit slightly off register.

Everything is defined in sheet units, so the preview, the loupe and a 2905 × 3508 export describe the same print.

02 — Interaction

Open a photo, see the plates, move one, export.

  1. Open

    Open or drop a JPEG, PNG or WebP. Files are validated by size, magic bytes and header before decoding.

  2. Separate

    Two plates appear as tabs under the sheet. Hold Separate to lift them apart, each rendered alone.

  3. Register

    Drag the print to move the plate in hand; a millimetre readout follows the pointer, and the registration marks double up.

  4. Inspect

    The loupe shows the export’s own pixels at 300 dpi, drawn 1:1.

  5. Export

    Composite and two films as PNG at A4 300 dpi, rendered in a worker with progress and cancel.

03 — Engineering

Separation, an exact dot, and registration in the plate’s frame.

Separation. Each pixel is composited over the paper in linear light and converted to OKLab. The key plate takes tone; the accent plate takes colour leaning toward the second ink’s hue; the key gives way under the accent. It is an interpretive mapping, not a colour-accurate separation, and the README says so.

Halftone. Each screen cell inks the round dot whose area — the circle clipped to the square cell — equals the sampled coverage exactly, so a flat field of coverage c inks a fraction c of the paper.

Registration. A plate’s offset and rotation are applied by mapping output pixels into that plate’s frame before the screen is evaluated, so the dots and the plate’s own marks move — never a shifted bitmap.

Dot area solved exactly, then tabulated.

Once a dot grows past half the cell it touches its neighbours, and a naive radius-from-coverage formula darkens midtones. The area function subtracts the four circular segments outside the cell; an inverse table built by bisection gives the radius for any coverage in constant time.

src/engine/halftone.ts · Edition @ 12e9b60

export function dotArea(r: number): number {
  if (r <= 0) return 0
  if (r <= 0.5) return Math.PI * r * r
  if (r >= R_MAX) return 1
  const segment = r * r * Math.acos(0.5 / r) - 0.5 * Math.sqrt(r * r - 0.25)
  return Math.PI * r * r - 4 * segment
}

The loupe renders the export, not the preview.

A zoomed preview would show smoothing and screen moiré that the file doesn’t have. The loupe asks the worker to render the window under the pointer at export resolution and draws it with no smoothing. The repository test compares those pixels with the same window of the downloaded PNG.

04 — Evidence

What is tested, and what isn’t.

Exports are inspected outside the browser, and the redesign was held to a golden test: five fixtures rendered in every mode against hashes recorded before the redesign.

For this page the print above was exported at A4 / 300 dpi: three PNGs (composite and two films), each 3508 × 2492 px, matching the dialog’s readout. The loupe’s 1:1 window and the same window of the downloaded composite differed in 0 of 35,344 pixels, and the on-screen proof matched the export to a mean of 0.24 / 255 (worst 8 px block 1.72) in linear light.

05 — Status

Limitations and what isn’t shipped.

Two inks only, AM round dots only. Colour is decoded to sRGB (wide-gamut sources are clipped) and there is no ICC proofing, so prints are a visual approximation of overprinted ink, not a press proof. Tested in Chromium and WebKit; Firefox and real phones were not tested.
