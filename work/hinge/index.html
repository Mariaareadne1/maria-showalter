Hinge

Design how interfaces move, then export the code.

Hinge is a workshop for interface motion. You handle one component on a stage — hover it, press it, drag and throw it — and shape the spring behind each state. Export writes a React + TypeScript component that runs the same spring code the stage ran.

01 — Overview

For people who design motion and want to ship it as code.

Motion is usually specified twice: once in a prototyping tool, then again by whoever implements it, by eye. Hinge removes the second step. The thing you tune is the thing you export, so “it felt better in the prototype” stops being a conversation.

There is one specimen at a time — a card, a button or a draggable token — and four states: Rest, Hover, Press, Drag. Three recipes (Lift, Snap, Magnet) are physically different starting points, not just different numbers.

02 — Interaction

Touch the object, pick a state, shape the spring, export.

  1. Touch

    Hover, press, drag and throw the specimen with a mouse, finger or keyboard.

  2. Pick a state

    The rail on the left selects Rest, Hover, Press or Drag; the object shows which state it is in now.

  3. Shape

    Drag the peak of the response curve, or scrub stiffness, damping and mass. Measured dots trace the real motion.

  4. Export

    The export bench shows the generated files: the component, its CSS, the runtime and a config. React is the only dependency.

03 — Engineering

One spring, solved exactly, shipped verbatim.

Every channel (x, y, scale, rotate, lift) is a damped harmonic oscillator, m·x″ + c·x′ + k·x = 0, solved in closed form for the under-, critically- and over-damped cases. Nothing is integrated frame by frame, so frame rate cannot change the motion and the curve on screen is the function the element follows.

The stage renders the same specimen components that an export contains. Exporting copies the runtime files byte for byte and substitutes the tuned values; nothing in an export imports Hinge.

Closed form instead of a physics step.

An integrator would be simpler to write and would drift with frame rate. The closed form gives an exact position and velocity at any time, which is what makes the editor’s curve, the measured trace and the exported component agree. When state changes, each channel is re-seeded from its current position and velocity, so a release that is still gliding home isn’t interrupted by a hover.

src/runtime/spring.ts · Hinge @ 41c0ddd

// spring.ts — exact state at time t (under-damped branch)
const wd = w * Math.sqrt(1 - z * z)
const decay = Math.exp(-z * w * t)
return {
  x: decay * (x0 * cos + ((v0 + z * w * x0) / wd) * sin),
  v: decay * (v0 * cos - ((w * w * x0 + z * w * v0) / wd) * sin),
}

A graph handle that edits feel, not numbers.

Dragging the curve’s peak sets when the motion peaks and how far it overshoots, which is how people describe motion. The handle inverts those two values into stiffness and damping at the current mass. The time axis holds still during the drag so the peak stays under the pointer.

src/runtime/spring.ts · springFromPeak

// peak time + overshoot → stiffness, damping
const lnOs = Math.log(os)
const zeta = -lnOs / Math.sqrt(Math.PI * Math.PI + lnOs * lnOs)
const omega0 = Math.PI / (tp * Math.sqrt(1 - zeta * zeta))
const stiffness = m * omega0 * omega0
const damping = 2 * zeta * Math.sqrt(stiffness * m)

05 — Status

Limitations and what isn’t shipped.

One specimen at a time; three specimen types. Motion is limited to transform channels and a lift shadow — no layout animation or shared-element transitions. React 18 is declared compatible but only React 19 is exercised by the fixture. Touch is tested by emulation only.
